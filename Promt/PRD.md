### 0.1 개발 시 반드시 적용할 규칙

1. 작업 시작 때 `ProjectSolution.md`와 이 문서의 최신 내용을 다시 읽는다. 사용자가 직접 수정한 내용을 확인하며 이전 대화의 기억으로 대체하지 않는다.
2. 사용자의 이번 지시를 요구사항 ID 및 원본 페이지에 연결하고 이번 단계의 구현 범위를 정한다.
3. 이 PRD의 일정과 설계 제안은 다음 기능을 자동으로 개발하라는 허가가 아니다. 사용자가 지시한 단계만 진행한다.
4. 기획서에 없거나 기획서와 다른 명령은 구현 전에 다음 문구로 확인한다.

   > 이러한 명령이 지금 기획서와 일치하지 않습니다. 맞는지 확인 부탁드립니다.

5. PRD와 원본이 다를 때, 사용자가 승인한 변경 기록이 있으면 그 기록을 적용한다. 승인 기록 없이 충돌하면 임의로 한쪽을 선택하지 않는다.
6. 관련 이미지를 읽지 못했으면 해당 작업 전에 알리고 사용자의 설명을 받는다.
7. 각 단계의 검증 결과와 남은 확인 사항을 기록하고, 한국어 커밋 메시지로 GitHub에 올린다. 커밋·푸시 성공 여부는 따로 확인한다.
8. 요구사항 상태는 `미착수 → 진행 중 → 검증 완료`로 관리한다. 규칙이 미확정이면 `확인 대기`로 표시하고 완료로 처리하지 않는다.

### 0.2 근거의 구분

- **사용자 확정:** 1.4절 수정과 12절의 A. 답변 및 이번 지시로 승인된 규칙이다. PPT와 다르면 사용자 확정을 우선하고 차이를 기록한다.
- **명시:** 기획서의 텍스트로 확인한 규칙이다.
- **이미지 관찰:** 삽입 그림에서 직접 확인한 배치·범위·화면 요소다. 그림 한 장만으로 다른 위치에서의 동작까지 확정하지 않는다.
- **설계 제안:** 요청된 기능을 구현하기 위한 내부 구조와 작업 순서다. 새로운 게임 기능을 뜻하지 않는다.
- **확인 필요:** 기획서의 누락·모순으로 확정할 수 없는 규칙이다. 해당 동작은 답변 전 임의로 구현하지 않는다.

최신 PPT 35슬라이드의 텍스트·배치 관계를 확인하고, 신규·번호 변경 이미지와 기존 이미지의 내용을 대조했다. 공격 도식의 미디어 번호와 페이지 번호를 최신본으로 갱신했다. 16페이지에는 교대·행동 완료·스킵 이미지가 추가되었고, 21·26·31페이지에는 직업군별 공격 범위 설명이 있다. 전체 슬라이드의 PowerPoint 렌더링은 수행하지 않았으며 삽입 PNG/JPG를 직접 확인했다. PPT 내부의 WDP 보조 리소스 2개는 직접 판독하지 못했지만, 각 슬라이드의 기본 삽입 이미지 참조는 확인한 PNG/JPG로 연결된다. 읽지 못한 보조 리소스에 별도 규칙이 있다고 추정하지 않는다.

화면 예시의 장식 문자·HP 수치는 확정된 캐릭터 수치를 대체하지 않는다. 페이지 번호는 현재 35슬라이드 기준이다. 35페이지는 카드술사 제목만 있고 추가 기능 본문은 없다.

## 1. 제품 목표와 범위

### 1.1 목표

체스의 위치 선정과 턴제 RPG의 스킬 선택을 결합한 2D 탑다운 전략 게임을 제작한다. 각 진영은 선택한 기물 4개로 시작하며, 상대 기물을 모두 처치하면 승리한다. 이동과 스킬 중 하나를 선택하는 일반 전투, 마지막 생존 기물의 영웅화, 양쪽에 한 기물씩 남는 최종전을 연결한다. 근거: 4~5, 7~19페이지.

5주 종료 목표는 **기본 전장에서 승인된 현재 범위의 기능을 적용한 AI 상대 경기의 완주**다. 제외·보류 항목은 1.3절에 따른다. 테스트용 일부 캐릭터만 작동하는 상태를 전체 완료로 간주하지 않는다. 미확정 항목이 남으면 해당 기능과 영향 범위를 명시한다.

### 1.2 포함할 내용

- 3개 직업군, 6종 캐릭터, 중복 없는 4기 선택 및 선택 순서 저장.
- 전체 8열×4행 보드, 진영별 4×4 영역, 중앙 경계, 초기 배치.
- 주사위 선후공 결정과 동점 재굴림.
- 선택 순서에 따른 양 진영 교대 턴, 라운드 초기화, 기절·처치 기물 스킵.
- 직업별 이동, 스킬 범위 미리보기, 다중 대상 피해, 체력과 처치.
- 6종 캐릭터의 기본·강화·영웅 스킬 및 패시브.
- 회복, 피해 감소, 기절, 강제 이동, 보호막, 표식 처치, 부활, 카드 변형 및 이동하는 상자.
- 영웅화, 영웅 스킬 사용 제한, 최종전, 승리·패배 표시.
- AI 상대의 합법 행동 선택과 턴 실행.
- 최종전의 공격 범위 단축, 서든데스와 동시 전멸 판정.
- 위 규칙을 확인하고 조작할 수 있는 전투 UI와 필요한 시각 표시.

### 1.3 제외·보류 범위

- 최신 PPT 20페이지의 전장 무작위 선택, 물빛 정원, 영웅의 땅, 용의 바다 및 해당 특수 효과는 **완성 이후의 기획**이다. 이번 5주에는 기본 8×4 전장만 사용하고 관련 선택·추첨·특수 타일·3기 편성·6×4 변형을 구현하지 않는다.
- 온라인 대전·로컬 2인 대전·매칭·계정·랭킹·저장/불러오기·성장·장비·상점·캠페인·독립 기본 공격·마나·일반 스킬 쿨다운은 지시되지 않았다. AI 대전은 Q02로 승인되었으므로 포함한다.
- Q11의 세부 행동 순서/종료 방식/전환 중 행동권 및 옛 ‘행 이동/열 불가’ 해석은 사용자 지시로 보류한다. 해당 내용을 임의 규칙으로 채우지 않고, 독립적인 다른 기능은 진행한다. 최종전 자체와 최신 PPT의 경계 해제·범위 단축·서든데스는 포함한다.
- Q21의 결과 확인 이후 재시작/다음 화면, Q22의 최종 아트·애니메이션·사운드·해상도·배포 세부 결정은 추후 개발 항목이다. 현재 단계의 승인된 기능을 확인할 최소 화면과 승패 표시는 유지한다.
- 8페이지의 ‘튜토리얼 제작 시 위 진행 방식’은 추후 튜토리얼을 만들 때의 기준이다. 별도 튜토리얼 시스템은 현재 자동 추가하지 않는다.
- 다른 게임의 참고 카드 이미지에 적힌 비용·방어도·덱 시스템을 본 게임 기능으로 옮기지 않는다.

### 1.4 확정된 개발 환경과 구조

사용자가 수정한 1.4절에 따라 **Python의 pico2d**로 개발한다. 실행 진입점은 기존 `Script/main.py`로 하고, 캐릭터·전투·보드·AI 등은 역할별 클래스 파일로 분리하여 연결한다. Unity/C# 선택을 다시 묻거나 Unity 프로젝트를 생성하지 않는다. PPT 5페이지의 Unity 표기는 사용자가 승인한 기술 변경으로 대체한다.

개발을 시작할 때 사용할 Python 환경에서 pico2d 설치 여부와 실행 가능 여부를 먼저 확인한다. 이미 사용할 수 있으면 추가 설치·재설치하지 않는다. 설치가 없다면 해당 단계에서 필요한 의존성만 처리한다. 이번 문서 수정에서는 설치나 게임 코드를 추가하지 않는다.

## 2. 용어와 전투 상태

| 용어 | 정의 |
| --- | --- |
| 기물 | 전장에 배치되는 캐릭터 인스턴스. 캐릭터 종류와 구별한다. |
| 직업군 | 근거리, 원거리, 조커 |
| 턴 | 기물 하나의 행동 단위. 일반 전투는 이동 또는 스킬 중 하나. |
| 라운드 | 행동 가능한 모든 기물의 행동이 끝나는 구간. 종료 후 행동 상태 초기화. |
| 영웅화 | 한 진영의 생존 기물이 1개가 되었을 때 그 기물에 적용되는 강화 상태. |
| 최종전 | 양 진영에 생존 기물이 각각 1개씩 있는 전투 단계. |
| 공격 범위 | 스킬이 영향을 주는 칸들의 집합. 칸 수만으로 모양을 결정할 수 없다. |
| 선택 순서 | 편성할 때 기물을 선택한 순서. 배치 위치 순서와 혼동하지 않는다. |

설계 제안 상태: `기물 선택 → 배치 → 선후공 결정 → 일반 전투 → 결과`. 일반 전투 도중 진영별 영웅화가 발생하고, 양쪽이 1기씩 남으면 `최종전`으로 전환한다. 한쪽이 전멸하면 최종전 진입 없이 결과로 간다. 영웅화는 경기 전체 상태와 별개인 기물 상태로 저장한다.

## 4. 공통 규칙 상세

### 4.1 편성과 초기 배치 — R01~R02

6종 중 4기 선택, 동일 캐릭터 중복 금지, 같은 직업군의 다른 캐릭터 선택은 허용한다. 선택 순서와 배치 좌표는 별개로 저장한다. 플레이어 진영은 왼쪽 4×4, 상대는 AI다. 적 편성·배치 방식과 양측에 같은 캐릭터를 허용하는지는 Q02·Q03의 잔여 사항이다. 그림의 적 기사·오크를 별도 캐릭터로 추가하지 않는다.

### 4.2 보드·경계·점유 — R02

구현 좌표 표기는 `x=0~7`, `y=0~3`, 왼쪽 위 원점으로 제안한다. 플레이어 진영 x=0~3, 적 진영 x=4~7, 경계는 x=3과 4 사이이며 칸이 아니다.

**Q03 확정:** 최종전 개방 전에는 어떤 이유로도 기물이 상대 진영으로 넘어갈 수 없다. 일반 이동, 백샷, 끌어당기기 등 모든 위치 이동에 적용한다. 공격이 경계를 넘어 적에게 닿는 것은 위치 이동과 구별한다. 아군 점유 칸은 벽으로 취급하여 이동으로 겹치거나 아군을 밀거나 뛰어넘지 않는다. 단, 카드술사의 명시된 아군 위치 교환은 일반 이동에 의한 충돌 교환과 다른 별도 스킬이다. 이 교환도 최종전 전 경계 제한을 지킨다.

적 점유 칸의 이동 충돌 및 최종전에서의 구체적인 점유 예외는 명시되지 않은 부분만 후속 확인한다. 추가 전장·크기 변경 로직은 만들지 않는다.

### 4.3 주사위·턴·기절 — R03~R04

주사위가 높은 쪽이 선공, 동점이면 선공이 정해질 때까지 재굴림한다(9페이지). **Q06:** 선후공을 한 번 정하면 경기 종료까지 다시 정하지 않으며 선공과 선택 순서를 유지한다. ‘한 번’은 동점 재굴림을 없애는 규칙으로 해석하지 않는다. 주사위 그림은 1~6면이며 확률 분포는 아직 지정되지 않았다.

선공 1번, 후공 1번, 선공 2번, 후공 2번 순으로 진행한다. 생존 수가 달라져도 순서를 재편성하지 않고 행동 불가 슬롯만 건너뛴다. 이미 행동한 기물은 같은 라운드 재행동하지 않는다. 행동 가능한 기물이 모두 행동했거나 전원이 기절하면 라운드를 종료한다.

**Q07:** 기절은 피격 대상의 행동을 제거하여 다음 기물의 차례로 넘긴다. 다시 기절하면 같은 규칙을 적용한다. ‘행동을 이미 마친 대상의 다음 라운드까지 제거하는지’와 중첩 누적은 답변에 명시되지 않아 잔여로 둔다. 단순한 라운드 초기화로 기절 규칙을 임의로 덮어쓰지 않는다.

16페이지 이미지 27은 교대 순서, 26은 한 라운드 1회 행동 및 초기화, 28은 기절·처치 스킵을 보여준다. 같은 페이지 텍스트의 ‘적군2 처치’ 예시는 실제로 적군1에 스킵 표시가 있어 예시 오기가 남아 있다. Q06의 ‘원래 순서를 유지하며 처치된 당사자의 슬롯만 스킵’을 적용한다.

### 4.4 이동 — R05

| 근거리 | 상·하·좌·우 인접 1칸 | 15페이지 image20, Q04 |
| 원거리 | 대각선 인접 1칸 | 15페이지 image22, Q04 |

Q04에 따라 카드술사의 특수 이동을 제외하고 다칸 이동을 임의로 추가하지 않는다. 이동 가능한 칸이 0이면 이동을 비활성화하고 공격 스킬만 활성화한다. 이 답변의 ‘행동 가능수 0’은 문맥상 이동 가능 칸 0에 적용한다. 기절·처치되어 행동 자체가 불가능한 기물에게 공격 권한을 주지는 않는다. 공격도 불가능한 경우의 종료 방법은 잔여 항목이다.

원거리의 일반 원칙은 사용자 답변(빈칸 2칸)을 우선한다. 기존 스킬 도식은 8절에 원본 관찰 좌표로 보존하며, 도식의 고정 좌표를 그대로 구현 좌표로 사용하지 않는다. 스킬별 모양을 어느 칸에 고정할지·범위 선택이 가능한지·영웅형을 어떻게 옮길지는 Q05의 남은 확인 대상이다.

범위가 보드를 벗어나면 **보드 안에 남은 공격 칸만 유효**하다. 보드 밖 칸을 반대편에 연결하거나 전체 범위를 안쪽으로 밀지 않는다. 실행 전 붉은 범위 미리보기를 보여주고, 실제 판정은 같은 좌표 집합을 사용한다. 범위 내 여러 기물을 공격할 수 있다. 난도 이외 공격의 아군 피해·빈 범위 시전 정책은 미확정 사항만 남긴다.

### 4.6 피해·회복·효과 — R07~R08

기본 피해는 스킬의 고정값이며 임의 방어력·치명타를 추가하지 않는다. 메이지 거리 보정은 Q16의 **칸당 +5%**, 워리어 주변 아군 피해 감소는 **10%**다. Q12에 따라 비율 회복은 최대 HP를 기준으로 정리한다. 영웅화의 증가 전/후 기준은 4.7의 수치 예시와 함께 검토한다.

피해·회복·기절·보호막·표식·강제 이동·부활을 공통 효과 처리기로 분리한다. 범위 공격의 대상을 미리 수집해 위치 효과로 중복 피격되지 않게 하는 구조를 제안한다. 보정 적용 순서, 일반 피해 소수점, 부활과 즉사, 사망·영웅화의 정확한 우선순위는 Q08 잔여다. Q08 답변이 동시 전멸을 정했다는 이유로 나머지 순서까지 확정했다고 처리하지 않는다.

### 4.7 영웅화 — R09

한 진영의 생존 기물이 1개면 영웅화한다. 최대 HP **30% 증가**, HP **20% 회복**, 기본 스킬 강화(암살자 제외), 영웅 스킬 해금을 적용한다. Q09는 증가와 회복을 동시에 적용하되 30% 증가는 회복이 아닌 최대 HP 증가라고 설명한다. 기본/영웅 최대 HP는 6절과 같다.

최신 17페이지 예시: **97/160 → 138/208**, 소수점 버림. 이 결과에 부합하는 계산은 `새 최대 HP=160×1.3=208`, `현재 HP=floor(97+208×0.2)=138`이다. 현재 HP에 1.3을 별도로 곱하지 않은 계산이다. 예전 97→126 예시는 최신 PPT에서 삭제되어 적용하지 않는다.

다만 Q09의 ‘최대체력 증가 비율 기준으로 올라간다’가 현재 HP 비율 보존까지 뜻한다면 위 예시와 달라진다. 현재 HP를 30% 증가시킨 뒤 회복하면 최종값은 138이 아니다. 따라서 **97/160→138/208은 원본의 기준 예시로 기록하되, 현재 HP 비율 보존 여부 한 가지를 확인한 후 일반 공식을 확정**한다. 확인되지 않은 계산을 이미 승인된 것으로 구현하지 않는다.

영웅 스킬을 r라운드에 사용하면 r+1에는 사용 불가, r+2부터 가능하다(Q10 확정). 사용 금지 라운드는 기물별로 저장한다. 영웅화 재발동·부활 후 유지와 같은 답변되지 않은 상호작용만 잔여로 둔다.

### 4.8 최종전·서든데스 — R10

양 진영 생존 기물이 각각 1개이면 최종전으로 전환한다. 영웅화 유지, 중앙 경계 제거, 한 턴에 이동과 스킬을 모두 사용할 수 있다는 최신 PPT 원칙을 기록한다. 이동/스킬 순서, 한 행동만 하고 종료, 중간 턴 행동권 등 Q11의 세부는 **사용자 지시로 보류**하며 해당 결정을 요구하지 않고 독립 기능을 개발한다. 보류 부분은 현재 구현 완료 대상에서 제외하여 보고한다. 옛 ‘스킬의 행 이동 가능/열 불가’ 문구는 최신본에서 삭제되었으므로 구현 규칙에서 제거한다.

- 원거리 공격 범위는 시전자 쪽으로 2칸 가까워진다.
- 조커 공격 범위는 시전자 쪽으로 1칸 가까워진다.
- 근거리 별도 단축은 명시되지 않았다.
- 최종전 시작 후 5라운드 이후, 매 라운드 시작에 각 기물이 HP 10%를 잃는 서든데스가 발생한다(18페이지).

서든데스의 10%가 최대/현재 HP 중 무엇인지, 최종전 첫 라운드의 카운트와 최초 발동이 언제인지, 보호막·부활과의 관계는 새로 필요한 세부 확인 사항이다. 해당 수치를 임의로 정하지 않는다. `final_round_count`를 일반 경기 라운드와 분리하고, 매 라운드 시작에 양측 감소를 한 묶음으로 계산하는 구조를 제안한다.

### 4.9 승패 — R07, R18

적 전멸 시 플레이어 승리, 아군 전멸 시 패배. **Q08:** 서든데스로 최종전 양측이 동시에 전멸하면 전 턴에 HP가 더 많았던 기물의 진영이 승리한다. 비교 대상은 ‘전 턴의 HP’이며 임의로 HP 비율이나 최초 최대 HP로 바꾸지 않는다. 비교 스냅샷 시점과 같은 HP일 때 처리만 후속 확인한다. 무승부를 자동으로 추가하지 않는다.

13페이지처럼 결과와 생존 수를 표시한다. Q21에 따라 결과 확인 후 화면/재시작은 추후 개발이다.

### 4.10 AI 상대 — R19

플레이어는 AI와 대전한다(Q02). AI도 동일한 턴 순서·행동 제한·범위·피해·기절·경계 규칙을 사용한다. 별도 규칙으로 이동하거나 잠긴 스킬을 쓰지 않는다.

구현 제안: 현재 기물의 합법 행동 후보를 공통 규칙 계층에서 가져오고, AI 선택기가 그중 하나를 골라 플레이어와 같은 실행기로 전달한다. 우선 합법 행동과 턴 진행을 연결한 뒤, 사용자가 지시하는 단계에서 선택 정책을 구체화한다. 난이도 메뉴·정보 엿보기·능력치 보정은 추가하지 않는다. 적 편성/배치 정책과 평가 전략은 별도 확인 대상이다.

UI는 현재 규칙 상태를 표시하고 규칙을 직접 계산하지 않는다. 원본의 석재 보드·판타지 SD 캐릭터·청/적 진영 구분은 시각 방향의 근거다. 최종 제작용 이미지·애니메이션·효과음 및 해상도·배포 세부는 Q22에 따라 추후 개발로 보류한다. 이번 5주의 필수 완료 조건으로 삼지 않는다. AI 예시의 장식·기물 외형·잘못된 HP를 모두 필수 기능으로 취급하지 않는다.

### 7.6 카드술사 — R16 / 33~34페이지

기본 액티브는 **카드 던지기, 카드 뽑기**의 2종이며, 영웅 액티브는 **마법사의 상자**다. 매 턴 카드를 뽑고 현재 카드에 따라 카드 던지기가 달라진다. 카드 뽑기는 현재 카드를 다시 뽑은 뒤 해당 카드 던지기를 곧바로 발동한다. 영웅 상태는 강화된 카드 던지기를 발동한다. 카드 뽑기와 그에 따른 즉시 발동을 두 번의 독립 행동으로 나누지 않는 실행 구조를 제안한다.

| 클로버 | 원하는 아군과 위치 교환 | 교환한 아군 최대 HP 10% 회복 | 55 |

상자 피해는 20부터 시작하고 이동할수록 10 증가한다. 발생 주기는 라운드가 아니라 **적 기물의 턴 시작**이다(Q20). 생성 직후 공격 여부, 최초 이동에서 20인지 30인지, 명중 후 유지·중첩·소유자 사망·스킵 차례의 이벤트 처리는 미응답 사항이다. 적 영역 앞에서 뒤로 진행하는 도식과 시작 위치는 유지한다. 카드 확률·지원 대상 선택·유효 대상 없는 카드·동일 카드 재추첨 여부도 답변된 것으로 간주하지 않는다.

## 8. 이미지 기반 공격 범위 기록

### 8.1 좌표를 읽는 방법

아래 표는 **원본 이미지에 그려진 예시 좌표를 그대로 전사한 기록**이다. 구현용 상대 좌표 공식은 아니다. Q05의 시전자 기준 거리와 도식의 차이를 별도로 기록했으므로 아래 절대 좌표를 그대로 게임에 고정하지 않는다. 그림 전체는 왼쪽부터 열 c=1~8, 위부터 행 r=1~4로 센다. `r1:{4}`는 첫째 행의 4열 칸, `r2:{3,4}`는 둘째 행의 3·4열 칸을 뜻한다. `없음`은 색칠된 칸이 없다는 뜻이다. 중앙 회색 선은 열에 포함하지 않는다.

그림의 시전자는 대체로 오른쪽 진영에 있고 왼쪽을 공격한다. 실제 플레이어는 왼쪽에 배치된다. 양 진영의 전방을 기준으로 좌우를 대응시키는 구조를 제안하되 범위 선택·정렬의 잔여 사항은 Q05를 따른다. 이미지 ID는 PPT 압축 내부 `ppt/media/image번호.png`를 뜻한다. 외부 파일이나 다운로드가 필요한 링크가 아니다.

## 9. 클래스와 파일 구성 제안

| --- | --- |

### 9.3 처리 흐름 제안

### 12.2 Q13의 구체적인 설명
