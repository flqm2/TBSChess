# 캐릭터 선택·배치·전투 프로토타입

## 승인 범위

2026-11-07 사용자의 후속 개발 지시에 따라 기존 이동 프로토타입을 확장한다. 캐릭터 선택 화면에서 6종 중 4기를 선택하고, 플레이어가 왼쪽 진영에 직접 배치한 뒤 선택한 캐릭터의 이동을 확인한다. 상대는 근거리 2기·원거리 1기·조커 1기를 고정 편성과 고정 위치로 배치한다. 양측 4기씩 총 8기를 사용한다. 보드는 선으로 그린 8×4 격자를 유지하고 Resource의 6종 원본 이미지를 사용한다. 코드는 기존 `Script/` 폴더에서 기능별 클래스로 나누고 `Script/main.py`에서 실행한다.

## 이번 구현의 동작

- 선택 후보는 슬레이어·워리어(근거리), 아처·메이지(원거리), 암살자·카드술사(조커)다. 같은 캐릭터는 중복 선택할 수 없고 같은 직업의 다른 캐릭터는 선택할 수 있다. 선택 해제 후 재선택하면 마지막 순번이 된다.
- 선택 순서는 행동 순서로 유지하며 배치 좌표와 별도로 저장한다. 배치할 기물을 상단 목록에서 고르거나 보드에서 클릭하여 선택한 뒤 빈 칸을 클릭하면 배치·재배치할 수 있다. 네 기물을 모두 배치하기 전에는 이동 단계로 진행할 수 없다.
- 홍팀은 슬레이어 F1, 워리어 F3, 아처 H2, 암살자 G4에 고정 배치한다. 상대 편성과 위치는 사용자가 이번 지시에서 임의 결정을 허용했다. 플레이어는 이와 독립적으로 6종 중 4종을 선택한다.
- 각 기물은 자신의 방향으로 인접 1칸씩 이동한다. 청팀은 왼쪽 4×4(A~D열), 홍팀은 오른쪽 4×4(E~H열) 안에서만 이동한다. 2026-11-07 사용자 수정 지시에 따라 중앙 경계선 통과를 금지하며, 대각선 이동에도 동일하게 적용한다. 이동 가능 칸 표시에서도 상대 진영을 제외한다.
- 살아 있는 기물이 있는 칸에는 진입할 수 없다. HP가 0인 기물의 칸은 비며 해당 기물의 차례를 건너뛴다.
- 차례는 청1 → 홍1 → 청2 → 홍2 → 청3 → 홍3 → 청4 → 홍4 순서다. 마지막 슬롯을 넘기면 라운드가 증가한다. 플레이어의 청1~청4는 캐릭터 선택 순서를 따른다.
- 현재 차례의 기물만 이동한다. 성공한 이동은 턴을 넘긴다. 잘못된 방향·보드 밖·상대 진영·점유 칸 클릭은 위치와 턴을 유지한다.
- Space는 이동할 수 없는 경우에도 진행을 확인하기 위한 턴 넘김이다. 정식 게임의 대기 규칙 확정과는 별개다.
- 현재 차례·팀·라운드·실패 사유와 직전 행동을 표시한다. 양쪽 기물은 수동으로 조작한다.
- 6종 기물의 일반·강화·영웅 액티브와 패시브를 적용한다. 마지막 생존 기물은 영웅화하며, 사용한 영웅 스킬은 다음 라운드에 잠긴다.
- 도식의 형태를 시전자 기준으로 좌우 반전한다. 원거리 도식은 Q05의 빈칸 두 칸 기준에 맞춰 한 칸 당기고, 보드 밖 칸은 제외한다. 사거리 안에 빈 칸만 있어도 시전하면 차례를 소모한다.
- 쓸어담기는 대상의 행을 유지한 채 시전자 쪽으로 가로 1칸 끈다. 백샷은 시전자를 뒤로 1칸 이동시킨다. 경계나 점유로 위치 효과가 막히면 피해만 적용한다.
- 기절은 대상의 다음 차례를 한 번 건너뛸 때까지 유지한다. 이미 행동했다면 다음 라운드까지 표시하고, 차례를 건너뛸 때 상단에 알린다. 난도는 같은 행에서 시전자 정면의 칸 하나를 추첨한다. 청팀은 오른쪽, 홍팀은 왼쪽이 정면이다. 빈 칸이면 빗나가고 정면에 있는 아군도 피격될 수 있다. 암격·난도의 표식을 기록하고 암살 비기는 다음 적중에 표식을 하나 더 부여한다.
- 카드술사는 행동 가능한 턴이 시작될 때 네 문양 중 하나를 같은 확률로 뽑는다. 카드를 뒤집어 하단에 표시하고 문양과 영웅화 상태에 따라 ‘카드 던지기’의 범위와 설명을 바꾼다. 일반 하트는 인접 아군 전원을 회복한다.
- ‘카드 뽑기’로 재추첨하면 같은 문양도 나올 수 있다. 공개 직후 새 카드 효과를 실행한다. 클로버는 파란 칸에서 교환할 아군 또는 영웅화 시 이동할 빈 칸을 선택하면 발동한다. 재추첨한 클로버에 유효 대상이 없으면 차례를 넘긴다.
- 마법사의 상자는 적 진영의 첫 칸에서 피해 20을 주고, 실제로 시작한 적 기물의 턴마다 한 칸 전진하며 피해가 10씩 증가한다. 명중해도 전진하며 마지막 칸을 처리하면 사라진다. 소유자가 처치되거나 같은 기물이 새 상자를 설치하면 이전 상자는 사라진다.
- 슬레이어는 피격 후 생존 체력이 50% 미만이면 최대 체력의 30%를 한 번 회복한다. 아처는 피격 후 생존 체력이 30% 미만이면 한 번 보호막을 얻고, 다음 공격의 피해와 부가 효과를 막는다. 카드술사는 체력이 0이면 최대 체력의 20%로 한 번 부활하며, 선택한 카드는 자신의 다음 행동에 사용한다. 발동은 상단 자막으로 표시한다.
- 워리어는 주변 8칸의 아군이 받는 피해를 10% 줄이며 보호 범위를 옅은 장판으로 표시한다. 한 스킬의 피해 감소 대상은 명중 처리를 시작할 때 정한다. 메이지는 가로·세로 칸 수를 합산해 한 칸당 5% 피해를 더하며, 범위 안 적의 칸 위에 추가 비율을 표시한다. 피해는 증가와 감소를 모두 적용한 뒤 소수점을 버린다.
- 기물 옆에 암살자의 표식 수를 표시한다. 표식은 시전자별로 계산하며, 새 대상에게 남기면 같은 암살자의 이전 대상 표식을 지운다. 표식 3개로 처치하고 카드술사의 부활 조건을 이어서 판정한다. 현재 기물 정보의 패시브 아이콘에 마우스를 올리면 설명과 사용 상태가 표시된다.

## 실행과 조작

기존 Python 3.11에 설치된 pico2d 1.5.1을 사용한다. `.venv` 생성·활성화나 라이브러리 재설치는 필요 없다. 저장소 루트에서 실행한다.

```powershell
python Script/main.py
```

어느 작업 디렉터리에서 실행해도 리소스는 소스 파일의 절대 위치를 기준으로 읽는다. 한국어 표시는 Windows의 맑은 고딕을 사용한다.

- 선택 화면 왼쪽 클릭: 캐릭터 선택·해제. 4기 선택 후 ‘배치하기’ 또는 Enter.
- 배치 화면 왼쪽 클릭: 상단 기물/배치된 기물 선택, A~D열 빈 칸에 배치·재배치. ‘캐릭터 선택으로’는 편성을 유지하며 배치 위치를 초기화한다.
- 4기 배치 후 ‘전투 시작’ 또는 Enter를 누른다.
- 차례가 시작되면 보드 아래의 큰 ‘공격’ 또는 ‘이동’ 버튼으로 행동을 선택한다. 선택한 조작 화면으로 하단 패널이 전환된다.
- ‘이동’을 선택하면 보드에 초록 칸을 표시한다. 해당 칸을 클릭하면 이동한다.
- ‘공격’을 선택하면 하단에 스킬을 표시한다. 스킬 버튼의 첫 클릭으로 파란 범위를 확인하고, 같은 버튼을 다시 누르면 발동한다.
- ‘뒤로가기’는 차례를 소모하지 않고 행동 선택 화면으로 돌아가며, 선택한 스킬과 범위 미리보기를 닫는다. 카드 뽑기로 이미 공개한 클로버는 다시 공격을 선택하면 대상 선택을 이어간다.
- 카드술사의 뽑은 카드는 행동 선택 화면의 공격 버튼에 표시한다. 공격을 열면 ‘카드 던지기’ 스킬에 문양과 효과를 표시한다.
- Space 또는 우측 ‘턴 넘김’ 버튼으로 차례를 넘긴다.
- 전투 화면 우측 상단 ‘?’를 누르면 별도 도움말 창이 열린다. 왼쪽 목록에서 생존 기물을 선택하면 현재 위치에서 기본 공격 범위를 합쳐 보여주고, 겹치는 칸은 밝게 표시한다. 도움말을 닫으면 진행하던 차례로 돌아간다.
- Esc 또는 창 닫기: 종료.

## 검증과 저장 단위

1. **편성 기반: 6종 캐릭터 데이터와 4기 선택 클래스 제작** — 공통 캐릭터 정의·중복 제한·선택 순서.
2. **배치 구현: 플레이어 4기 수동 배치와 선택 단계 전환 연결** — 자유 배치·재배치·고정 상대·8기 교대.
3. **화면 연결: 캐릭터 선택과 수동 배치에서 8기 이동까지 연결** — 선택·배치 화면·입력·기존 이동 화면과 진입점 통합.

파일을 남기지 않는 Python 표준입력 검증으로 6종 데이터·선택 제한·해제/재선택 순서와 기물 생성을 확인했다. 가능한 15종의 4기 편성 조합에서 상대 직업 구성, 진영/겹침 배치 차단, 재배치, 선택 순서와 좌표의 독립성, 미완료 상태의 진행 차단 및 8기 교대/라운드를 검증했다.

기존 이동·충돌·턴 구현과 중앙 경계 제한은 유지했다. 선택한 캐릭터의 직업별 이동과 실제 배치 좌표를 같은 이동 판정으로 처리한다.

실제 SDL 창에서 6종 선택 화면, 선택 수/순번 표시, 배치 및 재배치 화면, 8기 이동 화면을 렌더링하고 직접 검토했다. 선택 순서와 다른 순서로 배치한 뒤 캐릭터·좌표가 정확히 유지되는지 확인했다. 선택/배치 전 진행 차단, 입력 단계 분리, 중앙 경계, 8기 이동과 라운드 갱신, main.py의 선택→배치→이동→종료 루프도 확인했다. 저장소 밖 작업 폴더에서도 원본 리소스를 불러왔다. 캡처 3개는 검토 직후 삭제했으며 검증 스크립트·검토 폴더·가상환경·바이트코드 캐시를 남기지 않는다.
